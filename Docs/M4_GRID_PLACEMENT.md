# M4 — 포대 격자 배치 및 관리

## 기준

- `origin/develop` `90567de` (M3 PR #3 병합) → `codex/m4-grid-placement`.
- M3 로컬 Unity 정상 동작은 사용자 확인이다. 기존 미커밋 `Docs/M1_COMBAT.md` 수정은 보존하고 M4 커밋에서는 제외한다.
- Unity 6000.5.1f1 / URP 2D / Android Portrait / 기존 CookieBreakerMain, ProjectSettings, Packages, 에셋과 `.meta`를 유지한다. 기존 씬/`.meta`를 클라우드에서 직접 생성·수정하지 않는다.

임시 UI는 외부 폰트 없이 기존 내장 폰트를 사용하므로 영어 이름을 사용한다. 잠금 종류의 미확정 수치는 `TBD`, 버튼은 `Locked`다. 표시 공격력/주기/가격 필드는 준비되어 있으며 값이 정해지면 데이터로 표시할 수 있다. 실제로 나머지 무기를 투석기 공격으로 복제하지 않는다.

`TurretPlacementController > Definitions`의 Catapult 항목에서 기본 구매 비용 25, 증가율 1.15, 환급률 0.5를 조절한다. 이는 원작 확정 수치가 아니다.

- 다음 비용: `ceil(baseCost × costGrowth^max(0, 현재 설치 수-1))`. 기본 포대 1개일 때 첫 추가 포대는 25코인이다. 매각으로 설치 수가 줄면 다음 비용도 내려간다. 표현 범위를 넘는 비용은 LIMIT로 막는다.
- 환급: `floor(해당 포대 paidCost × refundFraction)`. 이미 설치한 포대의 지불액은 저장하므로 나중 구매 가격과 혼동하지 않는다. 무료 기본 포대는 0코인 환급이다. 잔액 오버플로가 생길 매각은 포대·코인 모두 유지하고 거부한다.
- 모든 포대를 팔 수 있다. 마지막 포대 매각 확인창에 공격이 멈춘다는 안내를 표시한다. 돈이 부족한 상태에서 모두 매각하면 설정의 재설정으로 처음 상태를 시작할 수 있다.

## 격자와 제한

- 격자 `Columns=8`, `Rows=9` (각 1~16), 최대 셀 크기 `Maximum Cell Size=0.6` world unit.
- 필드는 viewport `(0.08, 0.24, 0.84, 0.60)`이다. 카메라가 보이는 필드 안에 전체 격자가 들어가도록 셀 크기를 줄이고 중앙 정렬한다. 여백은 설치할 수 없다.
- `floor((world-origin)/cellSize)`로 칸을 고르고 `(x+0.5, y+0.5)` 중심에 설치한다. 상단/오른쪽 끝 경계와 음수 좌표는 필드 밖이다.
- 중앙 원은 격자 비율 중심 `(0.5, 0.55)`, 반경 `1.6칸`이다. **칸 중심**이 원 내부/경계면 설치 금지다. 격자 칸 전체와 원의 교차 여부를 검사하는 규칙은 아직 적용하지 않는다. 정확한 원작 규칙 대신 조정 가능한 초기 규칙이다.
- 격자선은 그리지 않는다. 중앙 금지 영역은 외부 에셋 없는 반투명 주황 원으로 표시한다. 줄무늬 원작 에셋은 복사하지 않는다.
- 화면 크기가 바뀌면 같은 논리 칸의 월드 중심을 다시 계산한다. 격자 수/금지 원 데이터는 Edit Mode에서 조절하고 Play를 다시 시작해 적용한다. 기존 저장과 맞지 않는 칸은 경고 후 제외한다.

## 전투와 기존 UI 전환

- Edit Mode의 원래 M1 고정 포대를 삭제/수정하지 않는다. Play에서 기존 포대는 비활성 복제 원형이 되고, 신규 게임/M3 저장/재설정 때 맨 아래 허용 칸에 무료 Catapult 1개를 만든다.
- 배치 포대는 기존 AutomaticTurret 및 배럴/발사점/투사체 참조를 복제해 재사용한다. viewport 고정 위치 추종만 끄고 격자 중심에 둔다. 기존 고정 포대는 동시에 발사하지 않는다.
- M2 전역 공격력/발사 간격 변경을 모든 배치 포대에 적용한다. 생산 강화는 기존 CookieSpawner를 그대로 사용한다. 쿠키/포대 공격/자동 저장은 설치·매각·모달 중에도 계속된다.
- M4 HUD는 Play 중 기존 M2 버튼 패널을 숨겼다가 Upgrades 모달에서 같은 패널을 다시 표시한다. 기존 Canvas 순서를 임시 조절하며 패널 자체를 새로 만들지 않는다. M3 Settings 버튼·설정/초기화는 유지한다.
- M4 모드/선택/페이지 관리는 `PlacementHud`와 controller가 담당한다. `SettingsPanel.VisibilityChanged`로 설정이 열릴 때 설치/매각/선택을 취소하고 Modal로 들어간다. 닫으면 Normal이다.
- 필드 입력은 메뉴/팝업과 **형제**인 투명 uGUI Image의 `IPointerClickHandler`만 받는다. 팝업/버튼의 상위에는 필드 핸들러가 없고, 상태가 Placement/Selling일 때만 처리한다. 원시 마우스/터치를 매 프레임 읽지 않는다.

## 설치·매각 트랜잭션

1. Normal 메뉴 → Install Turret → Modal 목록 → Catapult Buy → Placement. 진입 시에는 돈을 쓰지 않는다.
2. 필드 터치 시 허용 칸·미점유·현재 잔액을 재검사한다. 비활성 복제 오브젝트를 먼저 준비하고 모델 설치가 성공한 경우만 잔액/점유/오브젝트를 확정한다. 실패는 Placement를 유지하고 안내한다. Cancel은 Normal로 돌아온다.
3. 2페이지 → Sell Turret → Selling. 터치한 칸의 포대가 있고, 그 중심으로부터 0.45칸 반경 안을 터치해야 ConfirmationDialog로 들어간다. 가까운 다른 포대를 임의 선택하지 않는다.
4. 확인창은 종류/환급액과 마지막 포대 안내를 표시한다. Cancel은 Selling으로 돌아가며 아무것도 매각하지 않는다. 확인은 고유 ID를 재검사해 정확히 한 번 제거·지급하고 점유를 해제한다. 해당 포대의 남은 탄환도 정리한다. 다음 포대 매각을 위해 Selling을 유지하며 하단 Cancel로 종료한다.

## 저장 버전 2와 M3 호환

기존 버전/코인/세 레벨에 `layoutInitialized` 플래그와 `turrets` 배열을 추가한다. 각 포대 항목은 다음 필드를 갖는다.

```json
{"instanceId":"stable-guid", "typeId":"catapult", "gridX":0, "gridY":0, "paidCost":25}
```

- v1은 기존 SHA-256 계산을 변경하지 않고 검증한다. 코인/레벨을 복원하고 기본 무료 배치를 만든다. 다음 자동 저장에서 v2로 기록한다.
- v2 체크섬에는 배치와 ID/종류/좌표/지불액도 포함한다. `layoutInitialized:false`는 초기 배치 생성 지시, `true`와 빈 배열은 전부 매각한 상태다. JsonUtility가 null 배열을 빈 배열로 표현하더라도 의미와 체크섬이 변하지 않는다. 빈 배치를 초기 배치로 바꾸지 않는다.
- 복원 시 현재 복제 포대와 탄환을 정리하고 점유 모델을 다시 구성한다. 중복 ID/칸, 잘못된 좌표, 중앙 금지 칸, 음수 지불액, null, 미구현 종류는 로그를 남기고 건너뛴다. 코인/강화는 유지한다. 정제된 유효 배치가 다음 저장에 반영된다.
- AutoSaveService는 M4 `TransactionCommitted`에 연결되어 설치/매각 **성공 직후** 현재 코인/강화/배치를 함께 저장한다. 모드 전환/복원/실패/취소에는 저장 이벤트를 발행하지 않는다. 기존 30초/구매/포커스/종료 저장도 유지한다.
- 기존 `.reset` 우선 로드·백업 초기화 규칙을 유지한다. M4 재설정은 유료 포대를 모두 제거하고 무료 초기 배치 1개로 돌아간다. 이전 배치는 되살아나지 않는다.
- M4 참조가 연결되지 않은 옛 M3 씬에서 v2를 열어도 저장된 배열은 보관해 다시 기록하며 조용히 삭제하지 않는다. 실제 배치 복원에는 M4 로컬 설정이 필요하다.

## 로컬 Unity 설치 순서

1. 현재 로컬 씬/`.meta` 변경을 커밋 또는 백업으로 보호한다. 원격 기준에는 로컬 M2/M3 씬 구성과 새 `.meta`가 아직 없을 수 있다. M4로 전환할 때 해당 로컬 작업을 보존/반영하며 강제 리셋하지 않는다.
2. 원격 `codex/m4-grid-placement`를 받아 Unity **6000.5.1f1**로 열고 import/컴파일을 기다린다. 새 스크립트/폴더 `.meta`는 Unity가 생성한다.
3. `CookieBreakerMain`을 활성 씬으로 연다. 기존 M1/M2/M3 UI·포대·설정과 단일 InputSystem EventSystem을 확인한다. 해당 단계가 누락된 씬일 때만 기존 M2/M3 설치 메뉴를 먼저 실행한다. 정상 동작하던 기존 씬은 다시 만들지 않는다.
4. Edit Mode에서 **Cookie Breaker > M4 > Add Grid Placement to Open Main Scene**을 실행한다.
5. `Cookie Breaker M4`에 controller, `Placed Turrets`, 중앙 원 표시, Placement Canvas/HUD/필드 입력이 추가되고 기존 M3 AutoSaveService의 placement 참조가 연결됐는지 확인한다. 기존 포대/강화/설정 참조도 확인한다.
6. 재실행하면 기존 M4 루트를 선택할 뿐 중복 추가하지 않는다. 부분 설치/기존 다른 M4가 있으면 중단한다. 설치 직후 Undo는 새 루트와 M3 참조 연결을 함께 되돌린다. **기존 고정 포대는 Edit Mode에서 계속 활성 상태여야 한다.**
7. 씬을 저장하고 닫았다 다시 연 뒤 Play로 아래 항목을 검증한다. `Placed Turrets` 아래 실제 포대 개수와 저장 배열/목록 표시가 일치하는지 확인한다.
8. 생성한 `.meta`와 수정 씬을 M4 브랜치에 커밋/푸시한다. 사용자 검증/승인 전 main/develop에 병합하지 않는다. APK/실기기 재검증은 M4 필수 조건이 아니다.

## 로컬 PC Play 체크리스트

- [ ] 원래 고정 포대는 비활성이고 격자 기본 포대 하나만 공격한다. 기존 쿠키 생성/파괴/1코인 지급은 계속된다.
- [ ] 포대 선택 없이 하단 두 페이지를 전환한다. Support는 M5+ 비활성 표시다. 목록의 다른 7종은 잠겨 있다.
- [ ] Install → Buy → 안내/필요 코인/Cancel 표시. 유효 칸 설치 성공 시에만 비용 차감, 설치 즉시 자동 공격.
- [ ] 점유 칸, 중앙 원, 필드 밖/격자 여백, 잔액 부족은 차감·생성 없이 Placement 유지. Cancel은 차감 없이 종료.
- [ ] Settings/목록/매각 확인/Upgrades/Close/Cancel 버튼을 눌러도 해당 위치에 포대가 설치되지 않는다. 설치/매각 중 설정을 열면 Modal로 바뀐다.
- [ ] 설치/매각/팝업 중에도 쿠키 생성·기존 포대 조준/발사·코인 증가가 계속된다.
- [ ] Sell → 실제 포대 베이스 터치 → 종류/가격 확인. 빈 칸이나 셀 모서리를 눌러 다른 포대를 선택하지 않는다.
- [ ] 매각 확인 취소 시 동일 포대와 재화 유지(자연적인 코인 수익은 별도). 확인 시 한 번 제거/환급, 해당 칸에 재설치 가능. 연타로 중복 환급하지 않는다.
- [ ] Upgrades에서 기존 세 버튼이 보이고 피해량/발사 속도가 **모든** 배치 투석기에 반영된다. 생산 강화/기존 상단 재화도 정상이다.
- [ ] 설치/매각 직후 JSON 배열/코인 확인. Play 종료/재시작 때 위치/수량/ID가 복원되고 세 번 반복해도 늘어나지 않는다.
- [ ] 별도 백업한 실제 M3 v1 파일을 로드해 코인/세 레벨이 유지되고 무료 배치가 하나 생성되는지 확인한다.
- [ ] 모든 포대를 매각한 뒤 재시작해 빈 배치가 유지되는지 확인한다. 마지막 포대 안내와 M3 설정 접근을 확인한다.
- [ ] M3 재설정 취소는 배치 유지, 확인은 유료 배치/잔여 탄환 제거·코인/레벨 초기화·무료 배치 복원. 재시작에도 이전 배치가 돌아오지 않는다.
- [ ] 9:16/긴 세로 Game View에서 메뉴·목록 8행·안내·설정·Safe Area가 잘리지 않는다. 창 크기 변경 후 같은 논리 칸으로 이동한다.
- [ ] Console 컴파일/Play 오류 없음, Editor 메뉴 재실행/Undo/씬 재열기/새 `.meta` 확인.

## 클라우드 검증 및 한계

`python3 Tests/verify_m1.py --unity-data /workspace/unity-setup/6000.5.1f1/Editor/Data`로 독립 컴파일과 순수 상태/실제 임시 파일 검사를 실행한다. Unity Editor는 실행하지 않는다.

- 통과: 런타임/Editor 독립 C# 컴파일(오류·경고 없음), 기존 M1~M3 회귀, 격자 경계/음수/NaN/중앙 원, 점유·잔액 원자성, 잠긴 무기 거부, 환급/중복 ID/코인 오버플로, 잘못된/빈/반복 배치 복원, 실제 v1 canonical 체크섬 상수 호환 및 v2 JSON 왕복/좌표 체크섬, v2 배치/코인/강화의 파일 저장·로드.
- 통과: 기존 씬/에셋/`.meta`/설정/패키지 보호 대상 68개 파일의 기준 해시 보존 및 `git diff --check`. 새 에셋 파일/패키지/폰트를 추가하지 않는다.
- **미검증:** Unity import·JsonUtility 실행·Editor 메뉴/Undo·실제 다중 포대 공격·uGUI 입력/클릭 전달·레이아웃/Safe Area·씬 저장/재열기 및 PC Play 체크리스트. Android 전용 동작과 APK는 별도 미검증이며 필수 완료 조건이 아니다.
