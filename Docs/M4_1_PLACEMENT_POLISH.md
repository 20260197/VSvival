# M4.1 — 포대 배치와 전투 개선

## 기준과 코드상 원인

- M4는 아직 원격 develop(`90567de`)에 병합되지 않았다. 요청에 따라 `codex/m4-grid-placement`의 `cb30ea6`에서 수정한다. main/develop은 수정/병합하지 않는다.
- 기존 미커밋 `Docs/M1_COMBAT.md`는 보존한다. 원격 M3 브랜치에 별도 로컬 씬/메타 커밋이 있으나 M4 씬을 임의로 교체하거나 가져오지 않는다.
- 설정 확인 함수는 ResetGame 이후 **확인창만** 비활성화했다. 성공 시 전체 설정을 닫고 VisibilityChanged와 ResetCompleted를 통해 M4 선택/페이지도 초기화한다. 실패 시에는 설정 상태에서 오류를 볼 수 있다.
- 기존 원격 입력은 `OnPointerClick` 한 번으로 설치했다. Down/Drag/Up의 미리보기 단계가 없었다. 로컬에서 보고된 이벤트 발생 시점 자체는 클라우드에서 재현하지 않았다.
- AutomaticTurret는 이미 `FindNearest(transform.position, range)`를 각 포대에서 호출했고 공유 타깃 캐시는 없었다. 각 호출의 best/nearest도 지역 변수다. 0.9초 생성에 비해 여러 포대의 화력이 커져 하나의 쿠키만 겨냥하기 쉬운 공급 구조다. 탐색을 유지하고 포대별 CurrentTarget 필드를 추가해 Inspector에서 확인할 수 있게 한다.
- 쿠키 생성기는 사각 viewport를 사용하고, M4 원은 설치 제한/그림에만 사용했다. 이를 같은 월드 원으로 연결한다.
- 환급은 `paidCost × 비율`이었다. 현재 같은 종류의 수량으로 재계산하고, 견적 변경 시 확인을 다시 받는다.

## 드래그 입력과 시각 미리보기

- 필드 Image의 PointerDown에서 포인터 ID 하나만 캡처한다. 두 번째 손가락은 기존 드래그를 빼앗거나 확정하지 못한다.
- PointerMove/Drag는 같은 격자 중심으로 미리보기를 이동한다. 유효 칸/충분한 코인은 녹색, 점유/중앙 금지/잔액 부족은 적색 반투명이다. 필드 밖이나 UI 위에서는 숨긴다.
- 미리보기는 원형 포대의 SpriteRenderer/PlaceholderGraphic/Transform만 복제한다. AutomaticTurret, Collider, Rigidbody, 공격/발사점 로직은 생성하지 않는다.
- PointerUp에서 현재 좌표와 uGUI RaycastAll 최상위 대상을 다시 검사한다. 이 필드 Image가 최상위인 경우만 설치를 시도한다. 영역 밖, UI 위, 취소 후 놓기는 차감하지 않는다.
- 실제 포대는 Up의 칸/점유/가격/잔액 검증 이후에만 생성한다. PointerClick은 매각 선택에만 사용한다.
- EndDrag 취소, OnCancel, 비활성화, 포커스 상실/백그라운드, 상태 전환, 게임 재설정은 포인터 소유권과 미리보기를 정리한다. 설치 모드가 유지되는 취소는 다음 누르기로 다시 미리보기 할 수 있다. 설치 취소 버튼은 일반 화면으로 돌아온다.
- 마우스/터치는 기존 InputSystemUIInputModule의 공통 Pointer 경로를 사용한다. 실제 Android 터치 실행은 미검증이다.

## 원형 생성과 임시 밸런스

| 항목 | 이전 | M4.1 적용값 |
| --- | --- | --- |
| 기본 생성 간격 | 0.9초 | 0.25초(초당 최대 4회 시도) |
| 쿠키 localScale | 0.6 | 0.36 |
| CircleCollider2D radius / offset | 0.5 / 0 | 0.5 / 0 (월드 반경 약 0.18) |
| 중심 최소 간격 | 0.72 | 0.40, 최소 두 반경+0.02 이상 |
| 재시도 | 12회 | Inspector 기본 24회, 최대 64회 |
| 최대 활성 수 | 24 | 24 유지 (Inspector 1~100) |
| 중앙 원 반경 | 1.6칸 | 2.0칸 |
| 포대 원형 여유 반경 | 없음 | 0.75칸 |

격자는 8×9, 최대 셀 크기 0.6 world unit, 중심 비율 (0.5,0.55)를 유지한다. 실제 월드 원 반경은 **현재 셀 크기 × 2**, 최대 약 1.2다. 긴 세로 화면에서는 화면에 맞춰 더 작아진다.

- Controller의 동일 center/radius를 표시 원과 CookieSpawner에 전달한다. 설치 판정은 그 반경에 포대 여유 0.75칸을 더한다. 기본 포대 베이스 반경 약 0.389칸, 포신/발사점 최대 길이 약 0.722칸을 포함한 보수적인 여유다.
- 쿠키 반경은 콜라이더와 단위 직경 임시 그래픽 중 큰 범위를 사용한다. 샘플 중심 반경은 원 반경에서 쿠키 반경과 작은 여유 0.002를 뺀 값이다.
- `r=sqrt(u)×가용반경`, `theta=2πv`로 면적에 대해 균일 샘플을 만든다. 간격/개수 검사와 제한된 재시도가 포화를 처리하며 무한 루프나 추가 물리 시스템을 사용하지 않는다. 실제 개수는 공간/전투에 따라 24보다 적을 수 있다.
- Game View 크기가 바뀌어 원이 이동/축소되면 밖으로 나간 임시 쿠키는 무보상 정리한다. 새 쿠키는 새 원에 생성한다. 쿠키 피해/파괴/1코인 보상과 투사체 전투는 유지한다.
- M2 생산 강화 ×1.15 및 최소 0.2초 상한(초당 5회 시도)은 유지한다. 빨라진 기본값으로 현재 상한에 먼저 도달해도 **이미 구매한 생산 레벨은 삭제하지 않고** 상한 속도로 복원한다. 비용으로 도달 불가능한 비정상 레벨은 계속 거부한다. 임시 밸런스이므로 향후 조절 가능하다.

## 매각 공식과 확인

같은 종류 현재 설치 수 n, baseCost B, costGrowth G, refundFraction F로 계산한다.

```text
현재 가격 P(n) = ceil(B × G^max(0,n−1))
매각액 S(n) = floor(P(n) × F)
```

기본 B=25/G=1.15/F=0.5에서 n=3 → 17코인, 매각 후 n=2 → 14코인, n=1 → 12코인이다. Catapult 데이터의 가격·증가율·환급률을 조절한다. 원작의 확정 공식으로 주장하지 않는다.

- 과거 paidCost는 v2 호환 데이터로 유지하지만 환급에는 사용하지 않는다. 무료 기본 포대도 같은 종류/수량이면 같은 가격이다.
- 확인창은 선택 당시 견적을 보여준다. 확인 시 현재 수량/규칙으로 다시 계산한다. 달라졌다면 새 금액과 안내를 표시하고 재확인을 요구하며 그 클릭에서는 지급하지 않는다.
- 모델도 expectedRefund와 현재 금액을 검사한다. 유효 ID·잔액 한도 검사 후 한 번만 제거/지급한다. UI 갱신 후 기존 TransactionCommitted로 코인/배치를 함께 자동 저장한다.

## 저장 호환과 기존 포대

- 스키마/버전은 **v2 그대로**, M3 v1 읽기도 유지한다. SaveData/체크섬 필드는 바꾸지 않는다. 미리보기/Pointer/선택은 저장하지 않는다.
- 새 원+포대 여유에 걸리는 이전의 유효한 포대는 가까운 빈 허용 칸으로 이동한다. 유효한 다른 포대 자리를 먼저 예약하므로 빼앗지 않는다. 거리 동률은 행/열 순서로 결정하고 ID/paidCost/코인/강화는 유지한다.
- 다음 자동 저장에 보정 위치를 기록한다. 이미 보정된 배열을 다시 로드해도 추가로 이동/복제하지 않는다.
- 새 영역으로 인해 전체 포대를 수용할 수 없으면 모델 변경을 롤백하고 예외를 로드 보호 처리에 전달한다. 기존 M3는 원본 파일을 보존하고 자동 저장을 막는다. 이번 실행은 임시 기본 배치를 사용한다. 격자를 넓히거나 반경/여유를 조절하고 다시 시작해 복구하거나, 사용자가 명시적으로 재설정한다.

## 로컬 작업

1. 로컬 씬/`.meta`를 보존한 채 `codex/m4-grid-placement`를 업데이트한다. 기존 저장 파일과 `.bak`도 별도 폴더에 백업한다. 확장된 원에 걸린 포대는 첫 Play에서 보정될 수 있다.
2. Unity 6000.5.1f1 import/컴파일을 기다린 뒤 기존 M4가 구성된 CookieBreakerMain을 활성화한다.
3. **Cookie Breaker > M4 > Apply M4.1 Placement and Cookie Defaults**를 Edit Mode에서 한 번 실행한다. UI/포대 오브젝트를 교체하지 않고 위 표의 생성·크기·반경 값만 변경한다. 자동 저장하지 않으며 Undo로 되돌릴 수 있다. 재실행은 같은 값 적용이며 중복 오브젝트를 만들지 않는다.
4. 새로 M4를 설치하는 씬에는 기존 Add Grid Placement 메뉴가 M4.1 기본값도 함께 적용한다. 이미 설치된 M4를 새로 생성하지 않는다.
5. 씬을 저장·재열기하고 아래 Play 체크리스트를 실행한다. 새 C# 파일 `.meta`는 Unity가 생성한다. 수정 씬과 새 `.meta`는 같은 작업 브랜치에 반영한다.
